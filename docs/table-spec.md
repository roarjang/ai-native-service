# 대화 서비스 테이블 명세


## 1. 저장할 값 판단


판단 기준은 다음 세 가지입니다.


- 화면에 다시 보여줘야 하는가?
- 나중에 조회해야 하는가?
- 장애 분석에 필요한가?


셋 중 하나라도 해당하면 데이터베이스에 저장합니다.


| 데이터 | 판단 | 이유 |
|---|---|---|
| 사용자 질문 원문 | 저장 | 대화 화면에서 나중에 다시 보여줘야 합니다. |
| AI 응답 원문 | 저장 | 사용자가 과거 대화를 다시 볼 때 필요합니다. |
| AI 실행 상태 | 저장 | 실행 중·성공·실패 상태를 확인해야 합니다. |
| AI 실행 소요 시간 | 저장 | 응답이 느려진 원인을 분석할 때 필요합니다. |
| AI 오류 내용 | 저장 | 실패 원인과 장애 상황을 추적할 때 필요합니다. |
| Swagger 화면 상태 | 저장하지 않음 | 개발 도구의 일시적인 화면 상태입니다. |
| Gemini API 키 | DB에 저장하지 않음 | 비밀 설정으로 `.env` 파일에서 관리합니다. |
| Python Service 객체 | 저장하지 않음 | 서버가 실행되는 동안에만 존재하는 동작 객체입니다. |


## 2. 테이블별 책임


| 테이블 | 책임 | 주요 사용자 |
|---|---|---|
| `conversations` | 대화 하나를 묶고 제목과 생성 시각을 관리합니다. | 사용자 |
| `messages` | 사용자와 AI가 주고받은 발화를 순서대로 저장합니다. | 사용자 |
| `ai_executions` | AI 호출의 모델, 상태, 실행 시간과 오류를 기록합니다. | 개발자·운영자 |


`messages`와 `ai_executions`는 변경 이유가 다르므로 분리합니다. AI 호출이 실패하면 AI 메시지는 저장하지 않지만, 실패한 실행 기록은 남겨야 합니다.


## 3. 열·타입·필수 여부·키·제약


### `conversations`


| 열 | 의미 | 타입 | NULL | 키·제약 |
|---|---|---|---|---|
| `id` | 대화 식별자 | integer | 불가 | PRIMARY KEY |
| `title` | 대화 제목 | text | 불가 | 1~100자 |
| `created_at` | 생성 시각 | timestamp | 불가 | 기본값 현재 시각 |


### `messages`


| 열 | 의미 | 타입 | NULL | 키·제약 |
|---|---|---|---|---|
| `id` | 메시지 식별자 | integer | 불가 | PRIMARY KEY |
| `conversation_id` | 소속 대화 | integer | 불가 | FOREIGN KEY → `conversations.id` |
| `role` | 발화 주체 | text | 불가 | `user` 또는 `assistant` |
| `content` | 발화 내용 | text | 불가 | 빈 문자열 금지 |
| `created_at` | 생성 시각 | timestamp | 불가 | 기본값 현재 시각 |


### `ai_executions`


| 열 | 의미 | 타입 | NULL | 키·제약 |
|---|---|---|---|---|
| `id` | 실행 식별자 | integer | 불가 | PRIMARY KEY |
| `conversation_id` | 소속 대화 | integer | 불가 | FOREIGN KEY → `conversations.id` |
| `model` | 사용한 모델 이름 | text | 불가 | 비어 있지 않음 |
| `status` | 실행 상태 | text | 불가 | `running`, `completed`, `failed` 중 하나 |
| `latency_ms` | 실행 소요 시간 | integer | 허용 | 호출 완료 후 기록 |
| `error_message` | 오류 내용 | text | 허용 | 실패할 때만 기록 |
| `created_at` | 실행 시작 시각 | timestamp | 불가 | 기본값 현재 시각 |


NULL을 허용하는 열은 `latency_ms`와 `error_message`뿐입니다. 실행 시작 시점에는 소요 시간과 오류 내용을 아직 알 수 없기 때문입니다.


## 4. 제약조건이 막는 문제


| 제약조건 | 막는 문제 | 적용 예 |
|---|---|---|
| PRIMARY KEY | 행을 식별하지 못하는 문제 | 모든 테이블의 `id` |
| FOREIGN KEY | 존재하지 않는 대화를 참조하는 문제 | `conversation_id` |
| NOT NULL | 필수값이 빠지는 문제 | `content`, `role`, `status` |
| CHECK | 허용되지 않은 상태값이 들어가는 문제 | `role`, `status` |


## 5. 부분 저장 실패 시나리오


질문 하나를 처리할 때 저장 흐름은 다음과 같습니다.


```text
① 사용자 메시지 저장
② AI 실행 이력 저장(status=running)
③ Gemini 호출
④ 실행 이력 갱신(completed 또는 failed)
⑤ 성공한 경우 AI 메시지 저장
```


②에서 실패하면 사용자 질문만 남고 실행 이력이 없는 불완전한 상태가 됩니다. 따라서 ①과 ②는 하나의 트랜잭션으로 묶어 함께 성공하거나 함께 취소해야 합니다.


Gemini 호출 자체는 오래 걸릴 수 있으므로 트랜잭션 안에 넣지 않습니다. 호출이 끝난 뒤 ④와 ⑤를 다시 하나의 저장 단위로 처리합니다.
